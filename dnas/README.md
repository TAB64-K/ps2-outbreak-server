# my-dnas-server — authentication and matchmaking

The only container the PlayStation 2 talks to directly. It terminates every
HTTPS connection from the console and serves the matchmaking pages for both
titles.

Part of the [PS2 online server infrastructure](../README.md).

> Upstream documentation for the DNASrep project is preserved as
> [`README.upstream.md`](README.upstream.md).

## Why this container exists separately

The console negotiates only `EDH-RSA-DES-CBC3-SHA` — a cipher removed from
every current TLS library. No packaged Apache build can offer it, so this image
compiles Apache 2.4.56 from source against OpenSSL 1.0.2u, the last branch that
still carries the suite.

The cipher list explicitly excludes the AES, SEED and Camellia families, so the
server cannot negotiate anything newer. This is deliberate: it forces the one
suite the console understands.

Because this is the only container that can serve the console over port 443,
the matchmaking pages for **both** titles are published here rather than in the
game containers.

## What runs inside

| Component | Purpose |
|---|---|
| Apache 2.4.56 + OpenSSL 1.0.2u | Legacy TLS termination on port 443 |
| PHP 7.4 | DNAS authentication responses and matchmaking pages |
| DNAS certificates | Per-region certificates from the upstream project |

## Ports

| Port | Purpose |
|---|---|
| 443 | DNAS authentication and matchmaking (HTTPS, legacy cipher) |
| 80 | HTTP |

## Directory layout under the document root

```
DNASrep/www/dnas/
├── gai-gw/      Sony DNAS gateway (upstream)
├── us-gw/       regional gateways (upstream, untested)
├── eu-gw/
├── cn-gw/
├── bbnavi/
├── 00000002/    File #1 matchmaking pages   ← added by this project
└── 00000010/    File #2 matchmaking pages   ← added by this project
```

The two numeric directories are this project's addition. The game requests its
matchmaking pages by a fixed address identifier compiled into the client, so
the paths cannot be renamed — File #1 asks for `/00000002/` and File #2 for
`/00000010/`. Each directory carries its own `db_cred.php` pointing at that
title's database.

## Setup

### 1. Download the OpenSSL source

Not committed to this repository — the Dockerfile expects it here:

```bash
wget https://www.openssl.org/source/old/1.0.2/openssl-1.0.2u.tar.gz
```

### 2. Set the database credentials

Replace `changeme` in both matchmaking directories:

- `DNASrep/www/dnas/00000002/db_cred.php` → `$pass`
- `DNASrep/www/dnas/00000010/db_cred.php` → `$pass`

Each must match the password set in the corresponding game container, and
`$serv` must name that container (`bioserver1` or `bioserver2`).

### 3. Start and connect

```bash
docker compose up -d
docker network connect bioserver1-master_default my-dnas-server
docker network connect bioserver2-master_default my-dnas-server
```

Without the network step the container names will not resolve and every login
attempt fails, because user-defined Compose networks provide internal name
resolution and the default bridge does not.

## Certificates

`DNASrep/etc/dnas/` holds the per-region DNAS certificates from the upstream
project. They are required for the console to complete authentication and are
not generated by this project.

Only `cert-jp.pem` has been tested. The US, EU and CN gateways ship with
upstream but were never exercised here.

## Verifying

```bash
# a modern client should be REFUSED — this is correct behaviour
wget https://127.0.0.1/

# confirm the negotiated suite in the SSL debug log
docker exec -it my-dnas-server grep -i "EDH" /opt/apache/logs/dnas_error.log

# watch matchmaking requests as the console connects
docker exec -it my-dnas-server tail -f /opt/apache/logs/access.log
```

A successful console connection shows `POST /gai-gw/v2.5_i-connect` followed by
requests under `/00000002/` or `/00000010/`.

Note that requests from remote players appear with a Docker bridge address
rather than their VPN address — Docker's userland proxy rewrites the source
address when forwarding a published port into the container network.

## Security note

3DES is weak by modern standards and cannot be replaced without breaking
compatibility with the 2004-era client. This container is intended to run
inside a private VPN. **Do not expose port 443 to the public internet.**
